# 本机整库 AI 初稿检索提速

2026-11-09。接续[画面字段初稿](visual-fields-drafts.md)，用户要求优化约24秒的整库检索，保留权限和证据检查。使用项目 `.venv`，未修改原素材、模型、模板或剪辑端。

## 原因与实现

生产当前可见库416份，其中415份具有本轮四阶段模型初稿。原查询对每份素材逐阶段读取报告和证据帧，即使最终没有文字匹配也完整校验。新测同一真实查询HTTP基线18.835秒；数据库副本剖析17.938秒，其中初稿投影16.365秒、报告读取/验证14.249秒。前轮真实页面24.286秒为另一次测量，不能和这次HTTP计时混作同一请求。

本次只改查询路径：

1. 先执行原身份、库成员、对象权限、隐私/生产者和筛选门槛。在同一只读SQLite事务中，分批读取当前可见素材的活跃任务和初稿投影，代替逐素材重复联表扫描；每批最多400个ID。
2. 使用原投影版本、源SHA、任务ID、租约、当前结果摘要和报告SHA计算相同basis。仅当当前阶段可用且投影basis吻合时，用已索引文字做原有NFKC/casefold/子串/术语扩展的候选筛选。
3. 候选仍进入原 `_report` / Router产物校验：真实报告和帧字节SHA、绑定、路径/句柄、任务版本和证据检查全部保留。命中内容、顺序、分数、证据与游标所用结果摘要不变。没有投影或版本变化时完整读取并投影，不把缺失索引当无匹配。
4. 只排除索引可证明不匹配的阶段；显式视觉检索仍校验参与比较的CLIP向量。人工字段、已发布术语和概念关联规则不变。没有已发布活动概念时，不再遍历必定无法产生概念候选的旧任务。

这是每次请求内部的读取视图，不是跨用户/跨请求结果缓存；视图只允许在原连接只读使用。没有TTL、只看mtime或跳过候选哈希的快捷方式。无匹配内容不会被返回，详情、导出、下载仍使用原完整检查；新任务待执行、失败、取消和撤回不会恢复旧成功结果。

没有新增数据库迁移、依赖、后台任务或模型调用，索引表头和初稿版本未变。生产通过既有EDY Limited任务正常重载，无注销或电脑重启。

## 真实测量

同一具体标签的新HTTP测量为 **18.835 → 0.642秒，约29.3倍**；结果、排名、证据和索引修订指纹一致。真实Chromium页面约 **1.593秒**，四字段详情/批量入口可见、无页面错误、凭证未进入DOM。

四类查询在同一数据库副本上分别对照完整校验与优化路径，均逐项比较素材、排序、证据和索引修订；再在生产做三轮顺序HTTP与公共API检查：

| 查询类别 | 副本完整校验/秒 | 副本优化/秒 | 生产人员API三轮范围/秒 | 公共API单次/秒 |
| --- | ---: | ---: | ---: | ---: |
| 具体中文标签 | 12.160 | 0.345 | 0.618～0.642 | 0.660 |
| 英文检索词 red | 12.021 | 0.872 | 1.497～1.733 | 1.762 |
| 人脸观察 | 13.562 | 1.286 | 1.887～2.133 | 2.142 |
| 无匹配 | 13.782 | 0.372 | 0.612～0.635 | 0.632 |

生产检查为12次人员查询、4次公共查询；单次页面和有界样本不是正式P95/并发或业务签收。匹配多、投影缺失和显式视觉比较仍需读取更多证据，不能保证所有查询均低于2秒，也未证明正式规模负载。
