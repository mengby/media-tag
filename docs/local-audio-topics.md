# 本地音频十字段初稿接入

CT-14/15 已新增可调用的 `audio_topics` Router 阶段、实际音频桥接协议和报告验真。复用精标桥接器的受控本机 Python 子进程、源字节复制与 SHA256、探测依赖、超时/资源/输入预算、取消和提供方版本绑定；阶段、请求回执、任务键及报告的 `analysis_layer=local_audio` 独立记录。本轮没有选定、下载或运行音频模型，不表示已经具备音乐/音效理解能力。

入口包括 Python 服务 `request_audio_topics(analysis, deployment, asset_id, submission, principal=actor)` 和认证 HTTP `POST /analysis/assets/{asset_id}/audio-topics`。`submission` 复用 `PrecisionSubmission` 的明确请求 ID、资产/作业 revision、源 SHA256 和原字段范围。HTTP 沿用现有身份、严格请求体上限和线程池；对象无编辑权限或调用者为 Worker 会被拒绝。生产设置与服务不变，本轮未部署这些入口。

`LocalConfig.audio_topics` 使用独立的提供方部署配置，默认 `enabled=false / auto_dispatch=false`，不会隐式沿用 `precision`。启用需原模板审核政策；配置加载注册阶段和实际执行器。自动模式在当前源探测完成且前置任务停止后，仅为未请求过的音频字段派发，有界游标持久化；失败不自动循环、换模型不重跑整库。已请求的精标字段也不被后来本地任务抢占。执行器先派本地音频，再检查精标升级；精标会等待当前本地任务释放。

报告已接 `/analysis/assets/{asset_id}` 十字段状态、原 DraftIndex 检索/CSV 读取与当前审核资格。三处共用当前字段范围和实际报告验真；新增精标任务只遮蔽相应字段，当前报告损坏、任务失效或人工拒绝不回退旧成功缓存。显式修复沿用原认证修复入口，验证当前本地音频部署；只替换损坏/失败阶段，复用有效探测与已有成功阶段，回执幂等。正常导出仍经过原权限/文件门槛与短事务生产者元数据复核，旧35/14列保持。人员页面更完整的声音展示与真实业务验收继续单独推进。

提供方仍为 `PrecisionDeployment/PrecisionProvider` 的本机适配器协议：固定绝对脚本路径及实际脚本哈希、模型 ID/revision、`audio` 输入支持、CPU/CUDA 声明和输入/时间预算。该本地部署须独立提供，不能把精标配置默认当作本地粗标。未配置时返回明确冲突并保留待办，不创建假模型成功；不以转写、文件名或封面替代实际声音。本轮只跑合成 WAV 和明确标为 synthetic 的协议桥，不调用模型、网络或付费服务。

## 字段和证据

每份报告保留原十字段；纯音频的画面主体、表现形式为结构性不适用，实际向提供方请求其余八字段。依据为完整实际音频字节及探测确定的 `audio_segment` 起止与源 SHA256，超过预算则失败而不静默裁成另一段。新探测产物中的单轨整数PCM WAV可用精确样本数与时基建立零点，缺精确字段的旧报告仍保留时间未知。BGM/音效不套视频 3～5 秒规则。

本地输出记录 `origin=local`，精标仍为 `origin=precision`。非医学初稿继续分流精标，医学四字段保留人工审核，未发布选项保存原候选并分流词表。没有独立校准前不启用自动免精标。

模型提出的非结构性“不适用”完整保存在报告 `reply` 内；当前有效初稿状态为 `unknown / local_audio_applicability_requires_review`，分流人工或精标。这样不会把尚待验证的适用性判断当作免打标出口，也没有把合理的人工 NA 强行改为正式医学标签。只有纯音频的两项视觉 NA 可由结构规则直接确定。

新增报告保存实际结构化 reply，并在验真时重新执行同一字段规范化，校验请求/源/提供方版本、字段覆盖、原选项、候选、后续分流与 usage 一致。旧精标报告缺少新增可选字段时仍按旧契约验证；新的本地音频报告必须有 reply，不能靠改 `origin` 或层级冒充精标结果。建议不写入人工有效值、许可或任何批准。

## 已验证与剩余

测试使用真实可解码 0.5 秒合成音频与隔离本机桥进程，检查八项请求/十项状态、实际音频证据、未知/候选/NA 分流、人工有效值保持、请求幂等、两层任务/回执隔离、对象授权和 revision/source 检查、伪批准/错误源拒绝及输入预算。相邻精标与索引回归另行核对，协议测试不证明模型准确率或实际 BGM/音效业务可用。

尚需：音频模型选择及固定权重校验、真实音乐/声音事件输入与输出验证、声道/窗口/资源支持边界、人员页实际声音观察流程与独立人工业务集。CT-14/15 实际能力验收保持未完成；CT-19 音频精标也需要另选实际模型，不能因桥接协议相同而算完成。
