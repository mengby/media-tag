# 十字段分析状态汇总与首轮分流

2026-11-11。CT-04/CT-12/CT-17的部分工程接入，**不是本地十字段推理、大模型精标或整体验收完成**。本轮只采用已有四字段Worker的真实当前结果；其余能力显式保留待办。未选择、下载或调用新的语义模型，也未启用生产配置。

## 读取路径与真实证据

受权只读接口`GET /analysis/assets/{asset_id}`在`topic_analysis`中提供十字段初稿视图。仅在当前请求人有edit权、当前文件门槛放行且技术类型已知时提供内容视图；未知类型、只读共享或待隐私复核返回null。查询不启动Worker、模型、重排、回填或审核写入。

采用范围限定为本请求意图在Router中绑定的作业及其当前active任务/lease_epoch。只有成功且已释放的visual_fields结果可进入汇总；不从另一作业或较早成功尝试回退补值。旧版初稿缓存不作为证据。

读取时复用既有DraftIndex的报告与帧验证：源哈希、模型/版本、输入帧归属、实际文件哈希、prompt及建议结果绑定均须通过。再用新的AnalysisDocument验证具体字段的模态、证据与生产者关联。报告或帧失效后，四字段变为失败并等待证据修复，不继续输出旧初稿。

内部AnalysisProducer记录实际task_id、lease_epoch、源哈希、输入指纹、结果摘要、报告、版本、prompt及该次caption实际使用的证据；字段保留生产者引用。它是来源记录，不是复制租约或批准。内部文档以实际内容产生稳定analysis_id；证据/字段变化后形成另一份快照标识。

HTTP视图使用独立`ct-topic-analysis-view-v1`，同时声明内部`ct-topic-analysis-v1`文档版本。报告和证据只返回哈希、类型及时间等摘要，不返回私有artifact.ref、模型请求文件或工作目录。内部结构契约不直接作为HTTP响应输出。

## 十字段当前覆盖与后续动作

十字段名称及顺序沿用原表：用途大类、科室、器官/系统、疾病/症状、画面主体、过程/状态、表现形式、中文检索词、英文检索词、情绪/语气。汇总的是**AI分析初稿与缺口**，不将已有人工有效值改写为模型输出，也不宣称它等同于人工有效值覆盖情况。

| 输入/字段状态 | 当前值与后续动作 | 边界 |
| --- | --- | --- |
| 静态图片的四字段Worker成功 | 保留画面主体、表现形式、中英文检索词实际初稿；next_step=precision | 免精标效果尚未独立校准，不能自动宣布本地已足够；此处只记录后续动作，未调用精标提供方 |
| 视频/动画的首帧初稿 | 保留抽样初稿，next_step=evidence | 首帧不能证明完整变化，连续片段分析仍待CT-13 |
| 表现形式未匹配锁定选项 | no_match，next_step=vocabulary | 不自动扩枚举、不把未匹配当不适用；原Worker已丢弃的原始候选不编造恢复 |
| 本地模型输出未知 | 保留unknown，按模态等待precision或连续证据 | 不自动填词或写已完成 |
| 四字段任务未完成/失败 | unknown或failed，next_step=local；损坏报告/帧为evidence | 不使用旧成功回退；已有[阶段修复入口](analysis-repair.md)，完整字段级复用/补缺仍待CT-05 |
| 尚未接本地能力的其余六字段 | unknown，next_step=local | 不从OCR、文件名、人脸检测或CLIP向量补医学/用途/情绪语义 |
| 纯音频的画面主体/表现形式 | not_applicable，next_step=none | 只表示没有视觉内容，不表示免打标 |
| 纯音频其余八字段 | unknown，next_step=provider | 真实音频语义能力尚未接入，不用封面或名称代替声音 |

目前没有校准通过的自动免精标规则，`precision_exemption_calibrated=false`；没有任何字段由本模块发起大模型调用。后续CT-17须接完整本地能力、字段适用性、词表、独立校准和精标能力；CT-18/19须接实际可替换提供方。不能把上述保守待办规则当作CT-17完整验收。

科室、器官/系统、疾病/症状、过程/状态显式`requires_field_review=true`，AI初稿不批准这些字段。整个视图的analysis_complete当前为false，medical_confirmation、privacy_confirmation、effective_values_written也为false。有效值、字段审核、输出隐私审核和许可状态仍由原服务分别负责。
