# 清洗核心：标准副本与真实片段输出

2026-11-11，CT-07/CT-08 的独立本地核心实现。这里只交付可调用的文件处理能力和隔离验证，**没有接生产配置、Router/衍生登记、人员页或发布入口，也不表示两项任务已整体验收**。清洗副本仍需后续登记、判重、打标和相应输出复核，不存在免打标出口。

## 已实现的调用入口

`media_tag.cleaning.CleaningService(workspace, tools, limits=...)`在明确的本地工作目录创建`jobs/<job_id>/cleaning/`和专用清洗缓存。`run(source_path, CleaningRecipe(...), job_id=...)`接受已授权的原件路径及其实际SHA256；这是供受信服务调用的核心，不是可以自行取得素材权限的公共API。调用方仍须检查对象权限、原件/衍生来源和隐私门槛。

配方声明实际image/video/animation/audio类型，处理时从内容探测核对，不以扩展名判断。原文件不改名、不覆盖；探测和编码只读经过哈希核验的私有快照，原件在输出采用前复验。源变化或私有快照被改时不发布成功结果。

每次任务保留request.json、status.json及成功result.json或失败failure.json，包含规则/工具/资源限制、源和结果哈希、当前原名映射、实际阶段耗时/总耗时、检查与未批准状态。未选音轨/帧边界等记为waiting_policy，缺已验证时钟记为waiting_evidence，实际执行失败记为failed；不会把缺策略冒充执行失败或成功。缓存采用、原件复验、job复制、哈希检查、结果与状态发布在同一异常记录边界内；失败或等待时，旧result归档为history，不能冒充本次成功；恢复成功后旧failure同样归档。状态文件只记录安全错误类别/code，不把原始FFmpeg日志、路径或签名链接写入公开结果。

账本文件各自原子写入，不是跨文件数据库事务。同job_id需由调用方串行执行；强制终止、磁盘不可写及进程恢复仍须由后续Router/租约层对账，不能只凭历史文件判断任务仍存活。

## 各类素材的当前处理

| 素材 | 本核心实际行为 | 尚未完成的部分 |
| --- | --- | --- |
| 图片、静态贴纸 | 有界逐帧解码、尺寸/透明/边缘方差检查；原编码字节另存，按实际格式命名 | 不自动重采样、旋转、调色、去噪或修复；边缘指标未校准，不据此自动排除素材 |
| GIF/动画贴纸 | 检查完整帧数、各帧透明摘要、帧时长及循环；原编码字节另存，保持透明和循环 | 没有连续语义模型；不只处理首帧，也不强套视频3～5秒规则 |
| BGM、音效、其他音频 | 有界技术探测与完整音轨解码检查，保留原编码字节和完整时长 | 没有音频语义分类、降噪、响度归一或作者/许可推断，不裁成3～5秒 |
| 视频 | 根据实际视频流时钟逐帧定位，真实裁剪、显式固定变速/保音调或去音轨、编码后全片解码与时间校验 | 选段算法、转场/冻结检测、HDR/色彩管理、透明视频编码及质量验收仍待扩展 |

真人脸和水印处理不在本核心中冒充完成，报告始终`face_redaction_applied=false`、`watermark_removal_applied=false`。其实际处理由对应模块接入；标准副本不因存在文件就获得隐私或质量批准。

## 真实裁剪与3～5秒整理

`VideoSegment(start_seconds, end_seconds, alignment=...)`的时间以**所选视频流实际起点归零**。使用真实流start_time/duration及逐帧PTS，不把非零起点的容器duration端点当作长度；多视频流须明确选video_stream_index。每个输出帧记录源PTS、归一化源时间、源时长及输出时间/时长。

默认speed=1.0，不继承其他项目倍速。变速或target_duration_seconds必须有明确源片段；target限定3～5秒，并且与另填speed互斥。需要的倍速若超出现有0.25～4.0范围则拒绝，要求改选源片段，不默认把长视频压成几秒。未指定片段时只做全视频标准化；若输出不在3～5秒，状态为requires_duration_decision，不自动裁剪或编造策略批准。

alignment默认exact，边界需与实际帧边界一致；明确选择inside才向内取完整源帧。实际对齐范围另行记录，不能把向内取整后的2.9秒悄悄宣称3秒或额外填充。可在对齐后的明确片段上选择目标时长。

裁剪实际使用trim和重新编码，不是D11的segment注记。输出必须具有选定的帧数量、逐帧PTS和持续时间；报告`segments_are_annotations_only=false`。源sample_aspect_ratio必须已知且为1：非方形像素先待明确显示比例处理策略，未知比例待证据，不直接setsar=1挤压画面。使用有限大小输出和CPU时限；除Toolchain已有的输入解码线程限制，输出-c:v后明确-threads 1约束实际x264编码线程，并有真实640×360编码日志回归。超出预算不能成为成功副本。

## 音轨选择与时序

视频有音轨时必须明确audio_policy=preserve_pitch或remove。多音轨还须明确audio_stream_index；不默认拿第一条。无音轨由实际探测确认，无需捏造音轨选择。

preserve_pitch按源片段与选定音轨实际时间范围取交集，经atempo保持音调，保留交集的相对起始偏移，尾部按登记的缩放时长补/截。输出核验实际音轨数量、起点和时长，并保留容差。若未指定片段而音频延伸到视频范围之外，则要求明确范围，避免默认裁掉音频首尾。

remove明确输出无音轨。音频策略不等于原声版权或入片用途批准。整个时间映射只针对登记的输入版本；已知本工作目录生成的输出不能再悄悄当作原件重复套用倍速。完整衍生链及累计倍速仍须由原VariantService接入维护。

## 命名、缓存和来源边界

标准副本名为`asset-<源SHA前20位>-<配方键前16位>.<实际格式>`。配方键包含完整源SHA、配方、算法版本、工具身份和资源限制；身份本身仍是完整哈希，不依赖这个短文件名。每个任务单独保存original_name→standardized_name→源/结果哈希映射，不改原素材文件名，不写医学、来源或许可字段。

同输入、同配方、同版本的成功结果按哈希复用；另一个来源名称或任务可复用相同技术产物，但来源映射各自保存，不复制owner、权限或批准。同job_id改原名/配方会冲突。缓存通过完整键、源/配方/工具/限制、报告校验和、媒体大小和哈希核验；失效生成物被保留到私有隔离目录后重新生成，不覆盖原件。成功缓存以目录原子发布，校验不通过不采用。此次显示比例/编码线程修正使用ct-cleaning-core-v2缓存版本，避免复用旧行为产物。

本核心不提供身份或对象授权，缓存校验和也不是抵御具有工作目录写权限者的签名。缓存报告即使与sidecar一致，也必须符合本核心不可提升的不变量：original_preserved=true，质量/隐私/医学批准为false，许可为unverified，语义打标/人脸处理/去水印均为false；越界缓存隔离重建。最终result再次固定这些字段，不从缓存字典取得批准能力。staging递归清理只允许工作缓存根下、名称与生成规则吻合的直接子目录，明确拒绝缓存根、其他目录和解析后越界路径。接入主库时必须沿用现有权限、事务登记与输出哈希复核；不能直接把缓存或jobs目录公开服务。
