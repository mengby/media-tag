# 现有数据盘点与批量导入

2026-11-09。用户明确先把现有数据入库流程跑通，审核人员分配、正式词表/独立评测后置。本轮使用项目 `.venv`，实现只读目录盘点、受认证批量上传、自动进入当前用户素材库、后台分析入队与同批次续跑。原六模板保持只读，正式35/14列契约不变；不修改剪辑项目。

## 已可运行命令

从项目根目录运行，源目录与批次/对象目录必须分离：

```powershell
$env:PYTHONUTF8 = '1'
& .\.venv\Scripts\python.exe -m media_tag intake scan --source 'F:\图片' --jobs-root 'D:\ai\media-tag\jobs'
& .\.venv\Scripts\python.exe -m media_tag intake apply --batch 'D:\ai\media-tag\jobs\实际批次ID' --local-root 'D:\ai\media-tag\data\local'
& .\.venv\Scripts\python.exe -m media_tag intake status --batch 'D:\ai\media-tag\jobs\实际批次ID'
```

“实际批次ID”需替换为 scan 返回的 batch；不是预建目录。首次 apply 可加 `--limit 5` 试导入；返回 partial/退出码1表示仍有待处理或失败项，去掉 limit 后继续同一批次。limit 只限制新的/失败的导入，成功项仍校验来源和当前可见性。status 可加 local-root 获取真实任务状态；无 local-root 时读取本地批次状态，不假称模型完成。

也可用 `--config <私有客户端JSON>` 替代 local-root；配置采用 ClientSettings 的明确 HTTPS/loopback base_url 和绝对 token_file，必须是有上传能力的 editor/admin 凭证。当前本机 local-root 自动读取受保护 owner 凭证，不手工输入 token，也不把 token 放入参数/日志。MCP reader 客户端保持只读，不能用于导入。

## 盘点与入库行为

1. 原目录仅打开读取，不创建 README、改名、覆盖、删除、移动或建立源硬链接。盘点记录相对路径、大小、mtime、文件身份、SHA256、签名提示及重复关系；不把文件名或目录名当医学证据。
2. 跳过链接/reparse、私密配置/凭证路径；不支持的文件与读取失败分别登记。盘点对原字节做哈希；完整格式/解码仍由上传服务校验。默认最多10000个目录项、单文件2GiB，明确超限，不把截断清单当完整盘点。
3. 冻结 inventory.json 的字节摘要；apply 在写服务前重新验证源文件身份与全文件哈希，上传完成前再核对。清单改变或源改变就失败，不重新解释旧成功记录。
4. 上传走现有分块/完成/事务outbox API。按源组、相对路径与SHA256生成稳定幂等ID；中断从服务端实际offset继续。连接错误只对该幂等协议有限重试；401/403或持续传输故障停止当前批次。已关闭的失败会话留历史，新一代上传继续处理失败项。
5. 同内容复用对象字节，同字节不同路径保留独立来源/索引，不跨来源合并授权或人工值。相同路径、相同内容再次扫描/导入复用原登记；源内容变化应新建盘点，不覆盖旧索引。
6. purpose=library 的上传自动在当前用户素材库可见，复用服务端 probe/evidence/OCR/face/CLIP 队列。不要求医学审核或人员分配，不自动共享给其他账号；既有分享、撤回和人工字段不被重跑重置。
7. 入库成功与模型分析成功分别记录。当前 CLIP 缺候选词表时仍明确 partial/unpublished_vocabulary；本轮不把它伪装成成功标签，不发布词表或生成医学/隐私/许可批准。

## 格式兼容与预算

新增 JFIF 后缀，仍按 JPEG 实际格式严格验证。遇到签名与扩展名不一致，仅为上传副本追加正确后缀，例如 `原名.png.jpg`；原名完整保留在源清单、source.label 和映射中，源文件/字节不变。超过服务端180字符文件名限制时，上传名使用截断前缀和哈希后缀，原相对路径仍完整保存。

`upload_options.probe_max_pixels` 是服务端受信配置，默认仍16×1024²，支持范围1～64×1024²；普通上传请求不能自行改变它。该值同时用于入库验证、上传后的probe任务，以及processing素材主动入库后的probe任务，避免验证接受但后台仍用旧预算。压缩字节、其他解析预算与格式匹配保持原校验。

本机实测有2张图超过16M、最大25,232,233像素，因此将本实例明确配置为32×1024²，并正常重载素材服务。配置修改前已在受保护 backups 下保存旧配置，只有此项改变；没有重启电脑或修改相邻项目。新环境仍采用默认16M，需按实际输入/资源明确配置预算。
