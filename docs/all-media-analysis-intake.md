# 全类型分析待办：登记基础与当前边界

2026-11-11。CT-04已实现事务内分析意图与可选Router派发，追加[十字段状态汇总](topic-analysis-projection.md)。**当前只采用已有四字段初稿，其余能力保持待办；完整十字段推理尚未完成，不能把任务成功当作打标完成。** 相关实际进度见[执行记录](cleaning-and-topic-tagging-execution.md)。

## 已实现的登记路径

- `Catalog._register_blob_tx`在原件注册事务内创建分析意图；直接注册和本地/云同步使用的上传链路均受此约束。
- `UploadService.finalize`在上传完成事务中绑定实际解码得到的image/video/animation/audio类型。library和processing用途都登记，GIF映射为animation，不从文件名推断内容。
- `VariantService.register_output`在受信衍生结果登记事务中创建意图，绑定实际输出哈希及其owner；不继承父素材的标签或批准。
- 已知素材重传按本次真实请求人登记意图。原owner、来源及权限不变；只有read权的请求人保持待编辑权限，不伪装为owner运行分析。

同一素材、同一请求人、同一意图策略版本的登记幂等。相同字节但不同来源/账号的逻辑记录不合并。新增意图写入失败与素材注册/上传完成一并回滚，不出现已确认入库却丢分析待办的情况。

## 数据与接口

新增第11版事务迁移`analysis_intents`：保存intent_id、asset_id、requested_by、实际owner、文件SHA256、可选技术类型、意图策略版本和时间。它只记录域内需求，不取代Router执行队列，不生成分享或审核权限。迁移1～10及其校验摘要不变。

已在隔离API验证的只读接口：`GET /analysis/assets/{asset_id}`，使用现有Bearer/本机会话及对象授权。调用者只能看到自己的请求状态；worker及未授权账号不能借此读取。返回不含原路径、报告路径、请求人列表或其他账号判重事实。

| 状态 | 当前含义 |
| --- | --- |
| not_requested | 当前请求人无这版意图；不会在查询时自动回填旧素材 |
| awaiting_file_gate | 当前版本仍受原隐私/生产者等文件门槛限制 |
| awaiting_edit_permission | 可以读取但无权修改/分析该资产记录，不冒用owner权限 |
| awaiting_probe | 已有登记，但尚未取得可用技术类型 |
| awaiting_probe_adoption | 实际probe已成功，等待后台核验报告并采用技术类型；查询本身不采用 |
| pending_analysis | 已知模态，尚未绑定分析任务 |
| queued / running / paused / cancelled / failed / needs_attention | 已绑定Router任务的实际状态；不是字段完成状态 |
| awaiting_topic_analysis | 当前技术/视觉任务已成功，十字段仍待后续聚合与能力补齐 |
| awaiting_audio_provider | 音频技术任务已成功，实际声音语义能力未接入 |

这些状态的`analysis_complete`均为false。只有当前请求人的任务绑定通过对象权限及文件门槛时，`runtime_dispatched=true`，并返回安全的任务/阶段状态；不返回私有报告路径。新增`topic_analysis`只读视图逐字段列出真实初稿或待办，保留医学逐项确认和未校准免精标边界，详见[汇总与首轮分流](topic-analysis-projection.md)。

## 可选后台派发

`LocalConfig.analysis`新增配置，默认`enabled=false`；本轮没有修改生产配置。隔离配置显式启用后，Worker在每次取任务前（包括空闲轮询）按服务端凭证中的真实editor/admin身份扫描其自己的意图。没有凭证绑定的请求人保持待办，不从记录里的owner伪造身份。每用户每轮扫描默认32条、上限256条，游标轮转避免前面的受阻记录长期挡住后续记录。

已知视觉模态依次派发probe、evidence及已有配置的OCR/face/CLIP/四字段visual_fields；纯音频只派发probe，绝不以视觉模型代替声音分析。直接注册但技术类型未知的记录先派发probe：后台只读取当前已成功且已释放的探测结果，核验任务源哈希、报告哈希、模型/预处理/规则契约和实际kind后，绑定image/video/animation/audio。文件名不作为类型依据。

未知类型确认后，同一作业只追加缺少的视觉阶段，保留原成功probe和尝试记录；音频不追加视觉阶段。追加事务提交但确认丢失时，重开后校验既有规格并完成采用，不重复建阶段。暂停/取消、篡改/缺失报告或不一致的人工重排规格不自动采用，错误保留待处理；缺失/过期结果的完整修复仍属后续CT-05。探测失败也保留实际失败状态，不能填造类型。

使用原Router请求表把intent_id持久绑定作业，不新增执行队列或迁移。相同规格的已有library作业可按Router原规则复用；processing快速probe作业不被扩展或阻塞，分析使用独立完整作业。任务提交后确认丢失仍保留绑定；后续轮询不重复建任务，不自动替换暂停、取消或失败作业。变更配置不暗中重跑已绑定任务，补缺/重排由后续CT-05处理。

派发前检查请求人的edit权限和当前FileService门槛；实际Worker读取衍生输入时仍走原实时文件授权。待隐私复核衍生输出不会进入分析。只读状态查询不触发派发、迁移回填或模型执行。

当前运行中的生产实例未重启/重新加载，所以本实现不表示该实例已新增此接口或迁移。之后加载新代码时才由既有bootstrap在目标数据库执行v11迁移；本轮仅操作隔离测试数据库。

## 兼容与验证

离线备份验证器增加v11支持，继续接受真实v9/v10备份。旧备份还原到全新隔离目录后可由新版本正常迁移，未在生产数据库上执行升级或回退。旧数据不在只读查询时自动补意图，后续增量计划由CT-25评审。

新增验证包含实际合成PNG/GIF/MP4/WAV接收、两种上传用途、登记失败事务回滚、请求/数据库重开幂等、跨来源物理去重与owner分离、共享只读重传、待隐私复核衍生输出不放行，以及v10→v11失败回滚和原迁移摘要保留。

实际回归结果：契约/核心/上传/衍生/离线恢复批次205项通过；新增共享只读、迁移等针对性批次77项通过；扩大到Router、打码、变速、审核、检索、术语、页面、客户端、MCP、发布、收件同步、批量和文件接口的关联批次486项通过。这些批次有重叠，不相加充当独立用例总数。

追加隔离验证覆盖：实际合成图片CPU分析、processing独立作业、library同规格作业复用、提交后确认丢失与重开幂等、取消不重建、共享只读/跨请求人隔离、空闲Worker读取后来新增意图、纯音频不进入视觉阶段和待复核衍生输出不派发。相关结果见执行记录。

追加直接注册验证包括：实际PNG字节与误导性WAV扩展名、真实CPU探测后同作业追加、保留成功probe、追加确认丢失恢复、篡改报告拒绝及取消不重启。实际结果见执行记录。

这些验证不证明真实生活/医学/贴纸/BGM/音效语义标签、模型效果、近似判重或整库验收通过。下一步需补逐字段结果、缺失修复和有效复用，再接分流及真实模型验证。
