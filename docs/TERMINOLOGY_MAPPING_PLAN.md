# 口语词与专业术语对应：词表＋小模型实施方案

日期：2026-11-06。路线：用户已选择“词表＋小模型”。状态：D13契约/候选审核/发布回滚和D14文本模型/匹配工程已实现，见 [D13说明](terminology-release.md)；D14实现见 [文本Worker](terminology-worker.md)；尚无正式医学词表或素材语义检索。

2026-11-07归并：范围、全项目顺序和实际状态见 [需求基线](REQUIREMENTS.md)、[实施计划](IMPLEMENTATION_PLAN.md)、[进度记录](PROGRESS.md)。前轮72条候选数据本机仍缺失，不能当正式词表；D13发布机制于2026-11-08完成工程验证。本专题维护语义契约、D13～D16和T类验收。

## 1. 目标与边界

让剪辑师用日常表达搜索按专业标签登记的素材，并帮助打标人员把不同表达关联到相同概念。保留用户原话与实际画面证据，不把检索匹配当作诊断，不自动增加医学分类选项。

第一期采用：**已审核词表精确匹配 → 文本小模型召回候选 → 上下文规则筛选 → 有歧义时选择/复核**。不要求生成式大模型，不先训练自有模型，也不为此引入 Elasticsearch 或独立向量数据库。

以下仅为规则设计示例，不是已发布医学词条：

| 表达 | 拟定行为 | 禁止推导 |
| --- | --- | --- |
| 鼻子不通气 | 候选关联“鼻塞”概念 | 自动推导为某种鼻炎 |
| 肚子疼 | 候选关联“腹痛”，保留部位上下文 | 自动推导具体疾病 |
| 血管堵了 | 召回阻塞相关概念并标记歧义 | 直接等同“血栓” |
| 消肿 | 保留“肿胀减轻”的变化方向 | 与肿胀加重等价扩展 |
| 像海绵一样胀起来 | 分开保存实际主体与比喻喻体 | 将海绵直接标成医学结构 |

## 2. 两种词表分开管理

现有 **分类词表 taxonomy** 决定哪些值能填入科室、器官、疾病等锁定字段；新增 **术语对应词表 lexicon** 决定用户的表达如何关联到概念。两者各有版本，发布别名不等于发布新的疾病标签。

| 数据 | 必需字段与含义 |
| --- | --- |
| 概念 concept | 不变的 concept_id、标准名称、类型（器官/症状/疾病/过程等）、定义、适用范围、可选中英文别名、对应 taxonomy 选项 ID |
| 表达映射 alias_mapping | 原表达、规范化表达、目标 concept_id、关系类型、科室/器官等上下文条件、来源与定位、审核状态 |
| 概念关系 relation | 起点/终点 ID、关系类型、方向、扩展是否允许；不能把相关关系自动闭包为同义词 |
| 发布 release | lexicon_version、绑定的 taxonomy_version、内容哈希、发布者、时间、变更清单、上一版本 |
| 素材概念关联 asset_concept | asset_id/版本、concept_id、建议或有效状态、依据与操作者；和素材原文本并存 |
| 反馈 feedback | 查询表达、候选、用户选择/纠正、来源类型、待处理状态；点击不是审核通过 |

关系至少区分：equivalent（等价）、contextual（有条件对应）、broader/narrower（上下位）、related（相关）、metaphor（比喻）。只有已审核且满足条件的等价映射默认参与同义词扩展；其余只用于分组候选或用户主动扩展，保留方向，不双向乱扩。

同一表达可对应多个概念，不能设“一个词唯一对应一个疾病”的数据库约束；冲突规则需显示适用条件。标准名改名保留 concept_id 与旧名；概念合并/拆分使用显式迁移映射，不复用退役 ID。

用户 `asset-index-template/` 继续本地保留且忽略 Git。词表运营数据、医生原话和反馈放 `data/terminology/` 等忽略目录；Git 保存结构、算法、文档和合成测试夹具，不把原模板或词表内容换目录提交。

## 3. 词表从哪里来、如何发布

先覆盖常用科室。当前已形成60条常用对应与12条需语境确认的候选，共72条，全部待审核、未启用。后续可从授权素材标签、口播稿和人工搜索表达补到100～300条；数量是扩充建议，不作为已发布规模或通过验收的依据。

每条候选保留来源、具体原句/位置与关系理由。标准名称优先对齐用户已发布的分类选项；外部术语资源记录出处与实际允许使用范围，不把网上语料自动当正式规则。

流程为 draft → review → published / rejected；只有指定词表管理人能发布。管理人审核“两个表达是否对应、在什么上下文成立、能否用于搜索扩展”，不是批准素材医学内容。模型、点击日志及自动导入只能形成候选。

发布前检查：空目标/失效 ID、未发布分类引用、重复或冲突映射、上下位环、错误方向、缺来源、未审核项。服务端产不可变快照和差异清单，支持回滚。别名变化只更新查询侧词表/文本向量，不要求全库重新抽帧或跑 VLM；概念语义改变时列出受影响素材，重新审核关联，不直接覆盖原标签。

## 4. 小模型方案

基线候选为 `BAAI/bge-small-zh-v1.5`，负责**文本到文本**候选检索；CLIP 继续负责图文匹配，二者向量空间不能混用。词表概念文档由标准名称、定义、已发布别名与适用范围构成，预计算向量；模型相似度只表示候选排序，不等于医学等价概率。

部署优先 CPU、常驻小词表向量；在 i5-14400F 上实测延迟后决定是否使用 GPU。若使用 RTX 5060，仍领取全局 GPU 槽，不和 VLM/编码无预算争抢。固定模型修订、分词器、编码规则、向量维度与归一化方式。

第一期向量存本地文件、元数据存 SQLite，少量概念直接矩阵检索。模型替换或概念文档变化需要重建对应文本索引；打包词表快照、模型配置和向量索引，通过校验后原子切换版本，避免新词表配旧向量。

参考依据：

- [BGE 官方模型卡](https://huggingface.co/BAAI/bge-small-zh-v1.5)：提供中文语义检索能力，并说明阈值需结合实际数据选择。该模型是通用文本检索模型，未经本项目医学词对验证。
- [CBLUE / CHIP-CDN](https://github.com/CBLUEbenchmark/CBLUE)：可借鉴术语标准化的“召回＋排序”方法；它面向临床诊断表达，不是覆盖全部中文口语的成品词表。
- [Elastic 官方同义词文档](https://www.elastic.co/docs/solutions/search/full-text/search-with-synonyms)：可借鉴等价/单向映射与搜索时扩展。此处采用其设计思路，不新增 Elasticsearch 部署依赖。

## 5. 查询与打标的两条路径

### 查询时

1. 保留原查询；对 Unicode、空白及标点做受控规范化。否定、程度、部位、左右侧、时间和变化方向不能被清洗掉；拼写纠错只提候选，不能静默改医学名词。
2. 用发布词表匹配短语与上下文。优先最长合理短语，同时保存重叠/嵌套候选，不因子串命中就丢弃整句含义。
3. 命中唯一、已发布、上下文条件满足的等价映射，则生成概念检索；始终保留原文检索分支。不唯一时列候选，不强制取第一名。
4. 没有明确命中时，用 BGE 在已发布概念中取 top-k（起步 k=10，可配置），结合字段类型、原查询词项、上下文条件过滤与排序。模型只提候选，不自动写入永久别名表。
5. 明确的概念、否定与过程方向分别保留。“没有鼻塞”“鼻塞缓解”“鼻塞加重”不得归成相同检索意图。上下文解析不确定时返回 ambiguous，不盲目套硬过滤。
6. 基于概念关联和关键词召回素材；等价命中、字面命中、模型候选分层排序。可选图文检索分支只作补充，不将 BGE 分数与 CLIP 分数直接相加。
7. 页面显示“按哪个概念找到”以及可切换候选；状态分为 resolved、ambiguous、no_match、degraded。模型故障时保留词表与原文搜索，明确降级，不把故障写成无匹配。

上文规则用于素材检索，不承担临床诊断。正文是否真正支持某一医学概念，仍以实际素材及人工复核为准。

### 打标时

术语 Worker 可规范化 OCR/模型建议/人工输入中的概念表达，但必须带 evidence_origin。来源类型区分画面文字、模型视觉描述、人工输入、旧文件名与曾用原话。

旧文件名或用户搜索词只能帮助找候选，不能单独证明素材包含该疾病。Worker 只产生 concept 建议；医学字段仍逐条人工确认，人工有效值不被模型或词表更新覆盖。

现有表头不增加列：专业字段继续使用发布 taxonomy 选项；“中文检索词/英文检索词”可增加经确认的有限别名，保留人工编辑。导出不展开无限同义词，不把临时模型候选写入正式词条。应用的 concept_id/映射依据存在内部表。

飞书原生搜索不会自动执行本项目的语义 Worker。首期在自有检索入口提供完整口语搜索，飞书使用导出的有限检索词；要在飞书内直接调用完整检索，后续另做入口集成，不能宣称仅同步数据就已实现。

## 6. Router / Worker 协议

运行流程：query/tag_request → terminology_resolve → asset_search / tag_candidate → user_selection / review（按需）。词表维护单独走 collect_candidate → human_review → release_build → publish；发布只能由服务端处理。

| 职责 | 输入 | 输出与权限 |
| --- | --- | --- |
| terminology_resolve Worker | 原文、用途 search/tag、上下文、来源证据、固定词表/分类/模型/索引版本 | 原文片段、概念候选、关系、命中路径、原始分数、方向/否定、歧义；只读发布词表，无标签写入/词表发布权 |
| asset_search Worker/服务模块 | 确认或候选概念、词项、方向约束、调用者权限 | 按权限筛选的素材/片段及命中理由，不返回无权访问的原件或衍生文件 |
| lexicon_build Worker | 已审核修订集合、基准 release、发布配置 | 候选快照、向量文件、校验报告和哈希；无切换线上版本权限 |
| 唯一服务端 | 人工审核/发布请求、Worker 结果、基准版本 | 校验冲突后发布或采用；写审计、失效对应缓存，不修改其他人工标签 |

任务包沿用主方案的 task_id、job_id、attempt、lease_epoch、输入指纹、产物和错误协议；额外包含 request_kind、context、evidence_origin、lexicon_version、taxonomy_version、embedding_index_version、model_revision、target_fields。查询请求不得附任意 shell 或任意文件路径。

缓存包含原文与规范化版本、上下文、词表/模型/索引版本；素材搜索缓存另含可见范围与索引修订，不能跨用户复用私有结果。词表切换后旧查询可按绑定版本返回并标识，旧打标候选采用前须重验当前分类/素材版本。

交互查询设置短超时，超时走明确降级；不排在长视频渲染后无限等待。词表构建等后台任务沿用租约和有限重试。运行日志保留定位所需信息，对查询原话按权限保存，不把用户文本提交 Git。

## 8. 实施顺序与验收目标

并入现有主线：D00/D01 → D13 → D14（同时需 D03）→ D15（同时需 D06）→ D16 → D07 总体验收。可与上传/打码/变速开发分支并行；合并接口和 GPU 资源仍统一管理。可选 VLM、飞书/OSS保持后置。

首批候选词表人工审核后发布v1，再运行对照试点。独立验收建议采用第10节的120条查询构成，另备校准集；覆盖等价表达、多义词、未收录词、否定、左右侧、方向相反、比喻和不相关内容，近义改写和同源句按组划分，避免泄漏。

零容忍的程序约束：未审核映射不可发布、查询不能写正式标签、无权限素材不可返回、模型故障不得伪装为无匹配。拟定业务目标：在独立验收集上，明确解析的概念准确率至少 95%，同时报告解析覆盖率；方向和错误疾病扩展逐例复核，未达标缩小自动解析范围并显示候选。目标不是当前性能承诺，小样本结果不能代表全医学领域可靠性。

一期不做领域微调。待积累足够真实纠正数据、证明词表＋通用模型的瓶颈后，另评估文本重排模型或微调，不将其作为首期依赖。

## 9. 常用说法与专业术语的补充界面（拟定）

以下是配合已选定的极简画廊、独立视频处理界面的交互提案，尚未开发。页面统一使用“常用说法”和“专业术语”两个名称，不要求剪辑理解概念 ID 或模型分数。

### 9.1 剪辑端：在搜索时顺手补充

- 素材搜索附近放低强调的“补充说法”文字按钮，正常搜索不额外展开表单。已有映射的命中提示旁提供“对应不准确”，带入当前映射及版本。
- 搜索无结果时区分：没有识别到对应术语时提供“补充这个说法”；术语已经识别但库里没有可见素材时提供“记录素材需求”。不能把所有搜不到都归因于词表缺失，也不暗示存在无权查看的素材。
- 点击后打开轻量抽屉，保留搜索及当前素材位置。只显示下列字段，不展开完整专业审核表。

| 提交字段 | 要求与交互 |
| --- | --- |
| 常用说法 | 必填；带入当前查询，可修改。保留原文，不要求改写成规范医学名称 |
| 使用原句 / 想找什么画面 | 选填；用于消歧。可引用已有权限的口播位置或素材片段；来源不因反馈自动公开 |
| 你认为对应的专业术语 | 选填；搜索已有概念，允许“不确定”。小模型最多展示少量候选及“都不是”，不默认选中第一项 |

主按钮为“提交补充”，下方简述“审核后用于搜索”。提交后显示“已提交，待审核”，允许返回检索；不自动变成已发布别名，不改当前素材标签。提交者可在“我的提交”查看反馈、补资料或撤回尚未处理的提交。

发现相同表达时展示已有对应关系：完全重复可引导查看现有词条或补充证据；不同语境允许另提一条。去重按表达、目标、关系和上下文判断，保留各来源及提交者，不能只按字面覆盖。

### 9.2 管理端：独立的“术语词表”页面

侧栏底部“管理”分组放“术语词表”，仅有权限者可见；普通剪辑仍以素材库、视频处理、我的任务为主导航。审核与发布接口再次检查权限，不依赖前端隐藏。词表审核/发布权限与素材医学字段确认权限分别配置。

页头为词表搜索、状态/类型筛选，以及“新增对应”“导入词表”。页内使用“全部词条 / 待审核 / 发布记录”，不增加统计大屏。

- 全部词条按专业概念归组：显示专业术语、常用说法（过多时折叠）、类型、状态、最近修改。每条别名保留独立条件和审核状态，同一说法可出现在不同概念下。
- 待审核按提交项显示：常用说法、候选术语、原句摘要、来源类型、提交时间、状态。先处理缺信息、冲突与常用表达；频次仅帮助排序，不代表正确性。
- 进入词条后，左侧编辑专业术语、常用说法和适用条件；右侧显示来源、原句、现有冲突及“试搜”。同一概念添加多个别名可以快速逐行输入，但每个别名单独保存依据与关系。
- 审核字段包括：目标概念、关系（同义 / 需语境 / 相关 / 上下位 / 比喻）、适用语境、不能替换的场景、依据、是否允许搜索扩展。高级技术字段只读折叠。
- 专业术语优先从既有概念选择。确需新建时，先创建概念候选并审核；若涉及锁定分类选项，提交分类词表变更，不在别名页面擅自新增疾病/器官枚举。

### 9.3 试搜、审核与发布

试搜区域输入一句话，显示“原文检索 / 拟扩展到的术语 / 使用条件 / 对应素材示例”；明确标为草稿试搜。可以对比当前发布版本与拟修改版本，素材结果仍受当前账号权限限制。小模型只给候选及依据，不能代替审核结论。

审核动作使用“通过审核”“退回补充”“拒绝”。通过审核的映射进入“待发布”，不会马上影响所有剪辑的搜索；发布者确认本次新增、修改、停用和冲突清单后，服务端校验并构建新词表/向量版本，成功后原子切换。构建失败保留旧版并显示失败原因，不伪装为发布成功。

建议界面状态：草稿 → 待审核 → 需补充 / 已拒绝 / 已审核待发布 → 已发布；已发布条目可提交修改或停用，变更仍走审核与发布。审核与发布可由同一位被授权管理人完成，不额外强制多人审批。修改时绑定基准修订，遇到并发变更显示差异后重新核对；历史发布记录支持回滚。

试搜和候选示例仅说明检索效果，不能把“找到了素材”当作术语对应正确的证明。词表发布不自动确认素材医学字段，也不触发无关素材全量重新打标。

### 9.4 首批对应表与后续补充

此前生成的常用对应表作为候选导入源。页面支持 Excel/CSV 上传后预检：列映射、有效行、重复项、歧义项、缺来源及未识别目标分别展示。用户选择导入范围后只进入待审核队列；不直接启用整张表，不修改原始模板。

首批流程：导入常用候选 → 管理人审核 → 发布首版。后续流程：剪辑在搜索处补充少见说法 → 管理人查看语境、依据并试搜 → 合并到下一版。运营词表、上传表格、查询原文及反馈继续存忽略目录，不提交 Git。

## 10. 术语功能的验收用例与业务门槛（拟定）

D13对应的接口/机制工程测试已执行，见 [D13说明](terminology-release.md)；D14模型/接口工程已验证，D15页面及业务验收尚未执行。以下是可下发的验收设计；数值为建议目标，需在试点前确认并冻结，不是现有模型表现。D13 负责词表与发布约束，D14 负责候选解析，D15 负责使用流程，D16 统一评测并交 D07 集成验收。没有已审核发布的词表或独立标注集时，业务准确性记为“阻塞”，不能用种子候选或模拟结果宣布通过。

### 10.1 核心流程：逐条通过，不能用平均分抵消失败

| 用例 | 操作与故障注入 | 预期结果 | 负责任务 |
| --- | --- | --- | --- |
| T01 不懂专业名也能补充 | 在搜索页填写常用说法，专业术语选“不确定”后提交 | 原话和可选原句被保留，进入待审核；返回搜索时原筛选不丢失 | D15 |
| T02 无结果的两种原因 | 分别模拟术语未识别、已识别但没有可见素材 | 前者引导补充说法，后者引导记录素材需求；不暴露无权素材 | D14/D15 |
| T03 候选不等于生效 | 点击模型候选、保存草稿、通过审核但不发布 | 三种操作都不改变线上词表或素材医学有效值 | D13/D15 |
| T04 重复与多义 | 同关系重复提交；同原话在不同语境指向不同概念 | 重复项可合并且保留来源；不同语境分别保留，不能静默覆盖 | D13 |
| T05 缺依据与新概念 | 缺来源直接发布；输入分类中不存在的疾病名 | 发布校验明确阻止并指出问题；新概念进入候选，不新增锁定枚举 | D13 |
| T06 关系与语义约束 | 测试相关、上下位、比喻、否定、左右侧及反向变化 | 不冒充无条件同义；不确定时展示歧义，不擅自补疾病或抹掉否定/方向 | D14/D16 |
| T07 草稿试搜 | 对草稿和当前线上版分别试搜 | 结果可比较且注明版本，草稿不会改变其他用户查询，结果受权限约束 | D15 |
| T08 发布失败与恢复 | 在构建快照/向量、校验、切换前后注入失败并重试 | 成功时词表与索引版本一致；失败时旧版可用；重复请求不重复发布；回滚可验证 | D13/D14 |
| T09 权限和并发修改 | 普通剪辑直接请求发布接口；两位管理人修改同一修订 | 前者被拒绝且无写入；后者显示冲突，不最后写入覆盖 | D13/D15 |
| T10 批量导入 | 导入含重复、歧义、失效引用、缺来源及坏格式的表 | 逐行报告；明确导入范围；无静默丢行或自动启用；原模板不变 | D13/D15 |
| T11 模型不可用 | 断开模型/超时/索引加载失败 | 保留已发布词表和字面搜索，标明降级；与真正无匹配分开记录 | D14 |
| T12 发布后的增量影响 | 更新别名，再重复查询和检查人工标签 | 新查询使用新版本，旧缓存按规则失效；人工值不变，不重跑无关视觉任务 | D13/D14/D15 |

每条保存输入、基准词表/分类/模型版本、操作记录、预期、实际、证据和结论。接口级测试不能代替页面操作测试；页面成功提示不能代替检查数据库修订和线上查询版本。

### 10.2 独立评测集与指标定义

建议首轮独立验收使用 120 条人工标注查询：60 条在支持范围内、上下文明确的常用表达，20 条多义/需补语境表达，20 条否定/部位/方向/关系限制表达，20 条库外或不相关表达。分类尽量互斥，跨类别另记标记。另备校准集；原句近义改写、同口播来源必须分组，不能拆散到两套集合。测试样本可以包含已发布词表支持的概念，但不能把验收查询及答案用于阈值调优。

标注者逐条给出可接受概念集合、是否应明确解析、是否需澄清、允许的扩展和禁止推导。争议项先裁定，不能由同一个待测模型自动生成并验证答案。词表覆盖范围、支持类型及词表规模在运行前冻结。失败后修复可回归旧集，但调参后应补独立新集验证泛化，不能只报告修复后的旧题成绩。

| 指标 | 口径 | 拟定门槛 |
| --- | --- | --- |
| 明确解析准确率 | 正确的明确解析数 / 全部明确解析数，按标注规则同时核对语境与关系 | ≥95%；必须报告分子/分母；分母为 0 不能算通过 |
| 常用表达解析覆盖率 | 60 条明确常用表达中给出明确解析的条数 / 60 | ≥80%，防止靠全部拒识换取高准确率 |
| 有风险的错误扩展 | 多义词被强行唯一化、相关词推导疾病、抹除否定、颠倒方向等，在冻结挑战集逐例判定 | 自动生效分支中为 0；允许明确提示歧义。一次错误就返修该规则/缩小范围后重验 |
| 概念 Recall@5 | 对有已知正确概念的查询，前 5 候选覆盖的正确概念数 / 该查询全部正确概念数，再按查询宏平均 | ≥90%；多义项仍需标记歧义，不能因命中其中一项就宣称已正确解析 |
| 素材 Hit@10 | 至少一个人工判为相关的素材出现在前 10 名的查询数 / 存在可见相关素材的查询数 | ≥90%；另报符合条件的查询数和无相关素材的数量，不将此指标称为 Recall@10 |

明确解析准确率在全部查询上统计，常用覆盖率单独统计；工程失败和超时另报且不能混为拒识。若报告素材 Recall@10，必须标注固定候选库中的完整相关集合，计算命中相关数/全部相关数；没有完整集合时只报告 Hit@10，不能混用。

同时公布原文搜索、纯词表、词表＋小模型三个版本的相同输入结果，以及分类别指标、拒识/歧义比例、错误清单和人工修订时间。小模型只有在达到门槛且相对纯词表带来可说明的检索收益时才启用；未达标可缩小适用范围重验，不能把“已经接入模型”当业务通过。

### 10.3 易用性与响应体验

- 由 3 位实际剪辑各完成两次补充：一次知道专业名、一次不知道；给定任务说明后不由开发者代操作。拟定目标为 6 次均能独立提交，单次提交操作不超过 60 秒；只量操作时间，不把查找专业依据算进去。记录真实耗时和卡点，不替用户打分。
- 管理人完成导入预检、修正一条歧义映射、试搜、审核、发布、回滚的完整链路；所有核心动作和变更结果均可追溯。
- 拟定性能基线：指定 Windows 主机（i5-14400F、32GB、RTX 5060 8GB）、局域网、1,000 个可检索素材、2,000 条发布映射、5 个并发会话。预热后至少 200 次混合查询，统计浏览器发出查询到首批真实结果可操作的时间；建议 P95≤2 秒，超时/错误率≤1%。冷启动另测另报，不与预热结果混算。
- 相同负载分别在后台空闲和一个视频处理任务运行时测量。超时任务不能从性能样本中悄悄删除；同时报告响应时间与超时数量。若无法达到，先调整调度/缩小试点负载，改验收条件必须先记录，不能测完再降低门槛掩盖失败。

以上数量和时限是拟定首期验收条件，真实素材量、并发人数和 Windows 环境确认后再冻结。小样本通过只说明所测范围可进入试点，不代表全部医学口语已可靠覆盖。
