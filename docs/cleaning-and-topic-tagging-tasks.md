# 素材清洗与十维度打标：分阶段实施任务

日期：2026-11-11（Asia/Shanghai）。状态：**用户已授权目标模式执行，逐项进度见[执行记录](cleaning-and-topic-tagging-execution.md)**。

依据：[完整方案](cleaning-and-topic-tagging-plan.md)。本表最初仅作任务拆分；随后用户明确授权按CT-01～CT-25实施。下文是任务定义和验收要求，不代表实际完成；模型后续选定、原件保护、生产实例不改和不自动推送等范围继续适用。

`CT-01`～`CT-25`仅为本文内部子任务索引，映射既有D00～D20范围；不重编号原任务，不新增已完成数量，也不是control-center已下发的任务。列出任务不表示授权开始实现。具体模型、水印方法、审核人及验收门槛仍按依赖逐项明确。

各阶段对应的既有D范围同步列在主方案第10节；既有D任务的工程完成状态不代表本文新增子任务已完成。

## 1. 本次任务拆分的固定要求

- 所有新增素材一律登记、判重、入库并进入打标链路，包括生活场景、医学素材、静态/动态贴纸、BGM、音效及只请求打码/去水印/变速的输入。
- 处理结果可先按文件/隐私门槛交付；后台收件、判重和打标持久化继续，不随下载或页面关闭取消。
- 统一评估原“用途与主题”10字段的适用性；本地已够用时不额外精标，缺失或不合格的适用字段不能直接省略。
- 原件只读，清洗另存标准副本。精确去重不合并来源、所有权、许可和权限；近似重复只关联候选。
- 医学四字段逐项人工确认，其他六字段抽查；隐私输出复核、水印处理质量、来源许可及当前剪辑用途分别记录。
- 原35列素材表、14列缺口表及锁定枚举不变。新增配方、片段、声音描述、字段来源和分流理由保存在内部记录/附加台账。

## 13. 依赖与可分开推进的边界

主干是CT-01～03 → CT-04/05 → 对应清洗及模态分析 → CT-17 → CT-20～22 → CT-23/24 → CT-25。具体依赖以各子任务为准；CT-23的资料准备可提前。

- CT-06先定义关系与接口，CT-11/16再接真实匹配，避免近似判重未完就阻塞精确登记；其全部能力验收仍需真实匹配器。
- CT-07提供各模态共用的输出/质量基础；CT-08/09/10按素材需要执行，不能要求无脸音频也等待视频打码。
- CT-13为选段提供连续证据时，CT-08可先完成明确人工区间的真实裁剪，再补自动选段，不形成互相等待的闭环依赖。
- 视觉与音频分支独立；本地/精标位置可替换，但任何未配置能力都保持对应待办，不按“其他分支完成”自动跳过。
- CT-17可以先完成规则与协议，并用影子判断记录“建议如何分流”而不跳过实际仍必需的分析；CT-23/24独立校准验证后才具备启用相应免精标规则的条件，避免把实现/验证/正式启用混成互相等待的依赖。CT-18/19具体模型未定，不阻碍其他契约工作，也不能提前标为实际精标已完成。
- CT-22仅定义必要跨仓协作。真实OSS/ECS、企业认证、云端生产启用和剪辑项目修改不随这份任务表自动获准。
