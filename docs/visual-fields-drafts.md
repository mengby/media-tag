## 一次发起的实际流程

本机素材库新增“我的素材批量自动打标”。它只处理当前账号自己拥有、已在库的素材（单批最多500条）；其他人的分享素材不会被该按钮批量改动。上传到素材库的新素材也自动进入同一队列，不需要逐字段启动。

```text
上传/选择素材 → 技术探测 → 证据帧 → OCR/人脸/CLIP/画面字段 → AI初稿索引 → 35列CSV
```

有成功前置阶段时，仅追加缺失的画面字段任务；已完成且版本匹配时复用。页面显示进度，完成后自动给出“下载本批35列索引表”。关闭页面不会停止持久化Router任务；重新打开后再次点击会复用完成结果。界面浏览器验证使用独立合成素材/合成Worker协议，415张真实模型推理另做独立验收，二者不混称。

完成状态等待同一分析作业的全部活跃阶段结束，不会因画面字段先完成就提前导出。CLIP已经生成视觉向量、仅缺正式分类词表时允许进入初稿索引，仍明确记录分类缺失；其他分析失败保留失败状态。

已有盘点批次可用一个命令完成入队、等待、索引台账和模板导出：

```powershell
$env:PYTHONUTF8 = '1'
& .\.venv\Scripts\python.exe -m media_tag intake tag --batch 'D:\ai\media-tag\jobs\intake-ebe418409ddb' --local-root 'D:\ai\media-tag\data\local'
```

本轮使用显式415条选择，不处理当前账号另外1条旧素材。`tag` 有12小时等待预算；CLI中断/超时不撤销后台任务，可用同一命令续跑。不可恢复的失败保留失败状态，命令返回错误，不能当作完成；修复后同批次续跑，成功结果不重跑。底层 `intake describe` 只负责派发（可 `--limit 5` 小批试跑），`intake drafts` 只负责重新生成当前结果和模板表，用户不必逐项执行这些底层动作。

## 字段和证据边界

- 画面主体为短语；检索词为可见对象、外观及构图的中英文短语。模型只读取真实证据帧，不输入文件名或文件夹名，不从名称补医学事实。
- 表现形式严格使用原模板六项：`3D动画|2D插图|剖面|对比图|实拍|图标`。它是未确认的视觉呈现候选；静态图不证明实际动画、运动方向、拍摄来源或许可。
- 看不清时允许unknown；候选不在原选项内按no_match留空并保留原答案/规范化记录；无视觉证据为not_applicable；执行失败另记failed。不会为填满表格强行造值或扩大枚举。
- 检索词只作为本素材初稿，不自动发布别名/等价映射；科室、器官/系统、疾病/症状、过程/状态等正式医学分类保持现有发布/确认规则。来源许可、署名、人员身份不猜测。
- 四个字段通过现有 `TagSuggestion` / `suggestion_runs` 事务采用，保留源SHA、租约、模型、提示词、帧及报告哈希。人工有效值始终优先；AI重跑保留历史，不覆盖人工字段。
- 初稿索引投影升级到 `ai-observations-v2`，复用现有SQLite迁移10的通用阶段表，没有新增表头或数据库迁移。页面、原文检索和公共API/MCP的 `include_drafts` 复用同一证据链和权限。

原模板35/14列表不变。正式CSV仅显式请求AI初稿时填这些非医学候选，标签状态仍为“AI初稿”、许可仍“未核实”，不写假打标人；未知/不适用/无匹配原因保留在台账及quality中。`ai-field-states.csv`逐素材逐字段记录状态、值/留空原因和模型/提示词/任务/帧证据，完整一批含1660条字段状态，避免把留空混称失败。

## 推理、资源与提速

Router使用单GPU租约。独立子进程离线加载、BF16/SDPA推理，禁止远程代码；最大300秒、最多512²实际图像像素，必要时显式减载。子进程停止并等待退出后才释放资源，取消/超时不继续占GPU。

同一图片四字段使用独立提示并行生成。两张微批仅从同一账号已排队、依赖已就绪的任务预取；一次加载处理两张，结果按任务/源/帧/配置/版本分别缓存。预取结果必须等对应任务真实获租约并再次核对帧哈希后，才能成为该素材的建议；取消、改版和其他账号的任务不能复用。GPU进程已停止后才释放第一份租约，缓存命中任务不保留GPU模型。微批OOM只尝试一次减为单张，并在报告记录；不修改全局队列资源语义。

性能排查发现两处实际问题：旧式 `max_pixels` 属性没有约束此版本处理器真正使用的 `size`；BF16全patch Conv3d在本机的运行开销极大。现已按[上游像素预算说明](https://github.com/QwenLM/Qwen3-VL#pixel-control-via-official-processor)设置实际size，并检查实际网格像素数。全patch卷积以共享原权重/偏置的矩阵投影计算，条件为无padding、stride=kernel、每个输入恰好一个完整patch；不支持的结构明确拒绝。含/不含bias的数值对照通过，权重未改、精度未降、原素材未降采样覆盖；变换只发生在模型输入内存中。

本机剖析中某批图像投影约80秒，文本其余部分约1～2秒。修复后两张真实素材共14.6秒，其中生成约2秒，初步约7秒/张。不同图片、冷启动和当前负载有差异，不把单批测试当正式D16延迟验收；早期少量试跑结果保留原始版本和报告，未为性能优化重跑成功素材。原始剖析、微批对照和每次生成实际预算/投影/解码策略在被忽略的本地任务报告中。
