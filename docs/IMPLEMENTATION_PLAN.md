## 实施原则

企业接入为当前前置工作：用户要求沿用Python后端/Vue前端企业网站及账户体系。先取得项目/登录接口与用户/角色契约，再实施D01/D07/D12/D17身份适配和企业页面入口；协议未知不猜JWT或要求改用另一套登录。已有云端收件、在线结果、本地后台入库继续保留，参见[企业方案](enterprise-integration.md)。当前只完成方案，不将SSO计作已接入。

先固定契约和可运行的文件链路，再做真实处理和语义能力，最后进行跨项目集成。基础 API 随核心开发，不等到 MCP 阶段才设计权限与版本。页面可以提前用明确标识的模拟结果验证交互，但任务完成必须使用真实服务和要求的真实模型/媒体。

每个阶段均有可检查产物和出口，不把“开发完成”直接当“业务验收通过”。没有启动日期、人员投入和环境访问条件前，不承诺日历交付日；本计划按里程碑排依赖，M0 结束后再制定容量与时间基线。

## Router 与 Worker 下发办法

开发 Router/集成者负责冻结共享契约、选择已满足前提的卡、明确允许修改路径和基准提交、合并检查与状态更新。Worker 只负责本卡产物，不自行改另一个模块的 schema/依赖/主入口；必要公共变更提交给集成者。并行开发若启动，使用隔离分支/工作树，不能同时覆盖共享文件。

每次下发包含：任务 ID、关联 R/N、基准提交、AGENTS、卡片原文、输入版本、前置产物、可修改目录、非目标、A/T/I 用例和必须返回的证据。跨仓库 D19 单独明确范围，当前文档整理不算下发。

Worker 返回：变更与提交、真实执行命令及结果、产物/报告位置、版本和输入哈希、未解决缺陷、建议下一步。代码可运行但没有真实推理/内容复查时，只能进入对应的联调或待验收状态，不能写已完成。
